# 13 — Record the Walkthrough

**What to build:** A silent screen recording of BikeCheck running, showing one real task from start to finish.

This is the critical path. There is no live demo, no published store listing, and the source repository is deliberately being left as work in progress — so this recording is the only proof a Reader has that the application actually works. Without it the site cannot launch, and no amount of prose substitutes for it.

Show a complete task rather than a montage of screens: sign in, add a bike, log a ride, and let the Reader see component wear change as a result. A Reader should finish it believing the system does what the Case Study claims.

Not agent work — this requires the app running on a real device.

**Blocked by:** None — can start immediately, and should, because it gates launch.

**Status:** ready-for-human

- [ ] A real task is shown end to end, not a sequence of disconnected screens
- [ ] The recording is silent and readable without audio
- [ ] Roughly 60 to 90 seconds
- [ ] Recorded at a resolution that stays legible when scaled down
- [ ] No real personal data, credentials or private information is visible
- [ ] A poster frame is chosen that represents the app well when static
- [ ] Exported in a web-friendly format at a file size that respects the performance budget
- [ ] A short textual description is written to accompany it, since it carries no audio
